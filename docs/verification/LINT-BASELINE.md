# 린트 회귀 검사와 실행 환경

Node는 `.nvmrc`의 24.22.1, 의존성은 `package-lock.json`으로 고정한다. `npm ci` 후 `npm run lint:check`를 실행한다. `npm run lint`는 기존처럼 모든 진단을 출력하며 기존 오류가 남으면 실패한다.

최초 기준은 오류 125건 / 경고 23건이다. 회귀 검사 통과는 린트 전체 통과가 아니다. 파일 경로·규칙·심각도·메시지·fatal 여부·발생 수로 비교하며 줄 번호 이동은 허용한다. React compiler가 메시지 내부에 삽입하는 절대 경로·위치·소스 프레임도 제거하되 진단 의미를 설명하는 문장은 보존한다. 새 파일의 진단, 새 메시지, 발생 수 증가와 fatal 오류는 실패한다. 동일 파일의 동일 진단이 다른 위치의 같은 진단으로 교체되는 경우까지 식별하지는 못하므로 코드 리뷰를 병행한다. 보고서에는 원문 소스와 절대 경로를 저장하지 않는다.

기존 부채를 고쳤을 때만 `npm run lint:baseline`으로 기준을 줄이고 차이를 리뷰한다. CI에서는 이 명령을 금지한다. CI의 `LINT_BASE_SHA`는 PR의 대상 브랜치 SHA, main push의 이전 SHA, 수동 실행의 현재 SHA다. 그 커밋에 기준 파일이 있으면 허용량 증가를 거부한다. 알려진 과거 커밋에 파일이 없을 때만 최초 도입을 허용하며, 기록을 조회할 수 없으면 실패한다.

실제 검사는 `overrideConfigFile`로 루트 `eslint.config.js`를 강제한다. 하위 디렉터리의 설정 파일로 새 오류를 숨길 수 없다. `eslint.config.js` 변경은 현재/과거 기준의 SHA-256 비교로 차단한다. 규칙 변경이 필요한 경우에는 별도 gate 마이그레이션 PR에서 이전·새 설정의 진단 대응과 허용량 변경을 명시적으로 구현·검증해야 한다. 기준 파일만 다시 생성해서 통과시킬 수 없다. 현재 gate는 새 설정을 자동 승인하는 예외 옵션을 제공하지 않는다. 패키지 변경과 파일 내 lint-disable은 변경 리뷰에서도 확인한다.

`artifacts/lint-current.json`, `artifacts/lint-gate.json`과 UI 보고서는 Actions에서 14일 보관한다. PR/이슈에 실행 URL과 SHA를 남기고 장기 인수 근거는 별도로 보관한다. 실패한 단계 이후 검사는 실행되지 않을 수 있으므로 보고서 부재를 성공으로 해석하지 않는다.

## 실행되는 피드백 루프

1. 작업 이슈 → 범위별 브랜치 → 재현 시험 → 수정 → 재시험 → 상대 도구 리뷰 → PR 검증 순으로 진행한다.
2. `CI feedback` 워크플로는 main에 반영된 뒤부터 `Platform contracts` 완료 이벤트를 처리한다. 실제 활성 여부는 main의 해당 파일과 실행 기록으로 확인한다.
3. push와 workflow_dispatch를 각각 조회한 뒤 대상 저장소 main의 최신 SHA·실행 ID·시도 번호가 모두 맞는 실패만 `kind:feedback` 이슈에 기록한다. 이전 결과, PR/fork, 취소된 실행은 제외한다.
4. 같은 bot 이슈를 갱신하거나 재개하고 최신 main 성공 때 종료한다. 사람이 만든 이슈는 수정하지 않는다. 재전달된 동일 이벤트는 중복 처리하지 않는다.
5. 이 자동화는 소프트웨어 검사 실패를 알린다. 사용자 계정, 서비스 공급사, 실기기, 현장 인수는 #27과 개별 인수 이슈에서 별도로 완료해야 한다.

## 성장 루프

각 PR에서 가설·기준·변경·측정 결과·다음 행동을 `FEEDBACK-LOG.md`와 해당 이슈에 남긴다. GROW-01의 기준은 설치 engine 경고와 신규 린트 진단이며, 다음 측정은 기존 린트 부채 감소와 문의 접수→관리자 처리의 검증된 성공률이다. 실사용 문의 전환율·응답 시간은 실제 수집 경로와 동의를 확인한 뒤 집계한다. 합성 시험 수를 사용자 성과로 계산하지 않는다.

최초 baseline은 최신 통합 기준 `932e820d1044e73826165c82a3fe64db4f5610de`의 독립 체크아웃에서 생성했다. 다른 PR #28/#29의 변경을 먼저 반영했으며, 이번 브랜치의 오류를 baseline에 추가해 숨기지 않았다. 오류 125/경고 23건을 유지한다.
