# G0: 설정·사용 안내와 실제 계정 검수

## 이번 구현 범위

- `/admin/start`: 현재 계정의 MFA, 접근 가능한 현장, 검증 범위, 웹 배포 버전과 다음 설정을 조회한다. 기존 읽기 전용 RPC를 사용하며 DB 구조와 권한을 변경하지 않는다.
- `/admin/start`의 G0-01~06 항목에서 `시험 결과 기록`을 누르면 `/admin/governance?case=G0-XX`의 도우미로 이동한다. 요구사항과 절차 버전을 고정하되 실제 결과는 직접 선택해야 한다. 링크를 열거나 항목을 고르는 것만으로 증거를 생성하지 않는다.
- `/help`: 로그인 전에도 검색 가능한 기능별 준비 사항, 사용 순서, 완료 확인, 오류 해결과 관련 화면 링크를 제공한다.
- 선언된 95개 React 경로에는 정확히 대응하는 안내가 있다. 전체 화면의 `설정·사용 안내` 버튼에서 현재 경로의 안내를 연다. `/offline`과 `/app-update` 정적 복구 화면에도 안내를 제공한다.
- 인증 화면은 QR 등록, 같은 휴대전화의 시간 기반 수동 키 등록, 기존 인증 앱 선택, 명시적 미완료 TOTP 등록 정리와 재시도를 지원한다.
- QR·수동 키·번호는 브라우저 저장소나 시험 원자료에 기록하지 않는다. 인증 완료·계정 변경·화면 종료 시 이전 등록 정보는 화면에 남기지 않는다. 비동기 응답은 요청을 시작한 계정과 화면 세대가 일치할 때만 반영한다.
- 준비 중인 모듈은 개방하지 않는다. 사용 안내에서도 현재 가능한 절차와 추가 연결이 필요한 기능을 구분한다.

이는 G0의 소프트웨어 구현이다. 실제 계정의 독립 검수 완료, 실운영 개시 또는 전체 요구사항의 100% 달성을 뜻하지 않는다. 기존 36개 요구사항과 현장·버전별 인수 기준을 유지한다.

## 첫 사용 순서

1. 관리자는 본인 계정으로 `/admin/start`에 로그인한다.
2. 휴대전화의 공식 스토어에서 Google Authenticator 또는 Microsoft Authenticator를 준비한다. 처음에는 `인증 앱 등록하기`를 누르고 QR을 스캔한다. 같은 휴대전화라면 QR 아래 수동 입력 안내를 펼쳐 시간 기반 계정을 추가한다. 기존 등록이 있다면 기존 앱의 번호를 사용한다.
3. 앱이 생성한 6자리 번호를 입력한다. 번호가 거부되면 휴대전화 자동 시간과 새 번호를 확인한다. 번호 확인 후 서버에서 AAL2가 확인되어야 관리 화면에 진입한다.
4. `준비 상태 새로 조회`에서 조회 결과와 배포 버전을 확인한다. 실패를 빈 데이터나 완료로 해석하지 않는다.
5. `현장 검증·개선`에서 운영 조직을 등록하고 `단지 템플릿 생성`으로 검증용 현장을 만든다. 담당자와 다른 검수자에게 현장 권한 및 만료를 지정한다.
6. 현장·소스 버전·설정에 맞는 검증 범위를 등록한다. `현재 웹 버전 채우기`로 가져온 전체 SHA를 실제 시험 대상 배포와 대조한 뒤 `검증 범위 생성·선택`을 누른다. 조회 실패 시 임의의 버전을 대신 넣지 않는다.
7. `/admin/start`의 해당 G0 항목에서 `시험 결과 기록`을 누르거나, 현장 검증 화면의 `G0 검수 항목`을 선택한다. 현장·범위를 고르고 절차대로 시험한 뒤 결과·원자료 HTTPS 링크·해시·측정일·유효기간·관찰 내용을 기록한다. 결과에는 기본 통과값이 없다. 실제 환경에 맞게 staging 또는 field를 선택한다.
8. 다른 검수자가 원자료와 해시를 대조해 의견을 남긴다. 실패 증거는 결함을 생성하며 수정·재시험·독립 검수로 처리한다. G0 개별 시험의 통과가 전체 요구사항 인수 완료를 뜻하지는 않는다.
9. 회원은 공식 앱의 `설정 → 설정·사용 방법 전체 보기` 또는 각 화면의 안내 버튼으로 단지 연결·차량·방문·운영 문의 접수와 답변 확인 방법을 찾는다.

`검수 절차 내려받기`는 결과가 비어 있는 JSON 양식이다. `acceptance_granted`는 false이며 다운로드만으로 서버에 시험 증거나 승인이 기록되지 않는다.

## 오류와 복구

| 상황 | 처리 |
| --- | --- |
| 같은 휴대전화에서 QR 스캔 불가 | QR 아래 수동 입력 안내에서 시간 기반 설정 키를 사용한다. 확인한 뒤 숨기고 공유하지 않는다. |
| 등록 시작 후 QR을 잃음 | 다음 접속에서 `미완료 등록 정리`를 명시적으로 실행하고 다시 등록한다. 확인된 인증 앱이나 다른 인증 수단은 이 정리 대상이 아니다. |
| 휴대전화 분실·기존 인증 앱 접근 불가 | 계정 운영 담당자의 본인 확인 복구 절차를 이용한다. 이 화면에는 MFA 우회나 확인된 인증 앱 삭제 기능이 없다. |
| 준비 상태 조회 실패 | 연결과 계정을 확인한 뒤 다시 조회한다. 이전 응답이 현재 조회 결과로 남지 않도록 한다. |
| 새 파일의 해시 계산 실패·용량 초과 | 이전 해시는 즉시 지워진다. 50MB 이하의 파일을 다시 선택하거나 검증한 해시를 직접 입력한다. 계산 중에는 증거 등록을 할 수 없다. 파일은 기기 안에서만 읽으며 자동 업로드되지 않는다. |
| 현장·계정을 변경함 | 이전 입력과 지연 응답은 새 현장·계정의 결과에 반영하지 않는다. 현장과 증거 범위가 맞지 않으면 증거 입력을 중지하고 다시 조회한다. |
| 증거 저장 실패 | 입력 내용이 남는다. 동일 내용으로 재시도하면 같은 요청 식별자를 재사용해 중복 기록을 방지한다. |
| 최신 화면이 보이지 않음 | `/app-update`에서 작성 내용을 저장한 뒤 최신 앱을 불러온다. 연결 복구 후 기존 접수 내역을 확인한다. |
| 코인 결제나 운행 실행 불가 | 현재 회원 화면의 제공 상태를 확인한다. 관리자 결제·ERP 시험은 sandbox 전용이다. 실제 PG·지급·장비 연결이 완료된 것으로 안내하지 않는다. |

## 검증과 G0 종료 조건

자동 시험은 다음 경계를 확인한다.

- 모든 선언 경로와 안내 상태의 일치, 안내 링크의 실제 대상, 동적 주소·없는 주소의 안내 선택.
- 로그인 전 도움말과 차단된 모듈의 안내가 인증 등록·업무 변경·권한 개방을 일으키지 않음.
- MFA 잘못된 번호·AAL1 응답 거부, 중복 등록 방지, 이전 계정의 지연 응답 폐기, 설정 키 비저장·마스킹·인증 후 삭제, 미완료 정리 전 최신 등록 상태 재조회.
- 조회 실패·배포 버전 미확인 상태를 분리하고, 현장 관리자에게 본사 전용 현황 RPC를 호출하지 않음.
- G0 항목과 요구사항·절차의 연결, 명시적 결과 선택, 저장 실패 후 입력 보존·중복 방지 재시도, 현장·계정 변경과 이전 비동기 응답의 분리.
- 파일 교체·수동 해시 입력 시 이전 계산 결과 폐기, 용량 초과 시 이전 해시 제거, 계산 중 제출 방지, 선택 현장과 증거 범위 불일치 시 입력 차단.
- 정상·오류·가상 데이터의 95개 경로 렌더링, 실제 SQL을 사용한 시험 결제→본사/현장 배분→ERP 독립 반영→보고 흐름 회귀.

실행 명령은 `npm run inventory -- --check`, `npm run test:contracts`, `npm run test:ui`, `npm run build`이다. CI는 추가로 PostgreSQL 17의 governance 58·finance 63·ERP 66개 DB 검증과 공급자 계약 타입, Python 시험을 수행한다.

jsdom 및 SQL 시험의 인증·전송 계층은 가상이다. 실제 브라우저·휴대전화·Supabase Auth·현장 장비 인수와 동일하지 않다. 다음 실제 계정 시험은 `/admin/start`의 G0-01~06 절차에 따라 별도 원자료와 독립 검수로 종료해야 한다.

| 검수 ID | 실제 확인 대상 |
| --- | --- |
| G0-01 | 본인 휴대전화에서 최초 MFA 등록과 정상 진입 |
| G0-02 | 로그아웃·재로그인, 잘못된 번호 거부와 정상 재인증 |
| G0-03 | 서로 다른 작성자·검수자 계정과 인증 정보 분리 |
| G0-04 | 자기 승인 거부 및 다른 검수자의 원자료 확인 |
| G0-05 | 로그인 중 현장 권한 회수 뒤 신규 조회·변경 거부 |
| G0-06 | 실패·만료·설정 불일치 증거 거부와 유효한 재시험 처리 |

## 피드백과 성장의 반복

실패 시험은 현장·버전·요구사항에 연결한 개선 과제로 남긴다. 수정 후 같은 조건에서 재시험하고 별도 검수자가 근거를 확인한다. 새로운 기능·개선 아이디어는 완료 조건과 시험을 먼저 추가하되 기존 요구사항의 완료율 분모나 증거 기준을 낮추지 않는다. G0의 실제 인수가 남아 있는 동안 다음 운영 단계가 완료된 것으로 표시하지 않는다.
