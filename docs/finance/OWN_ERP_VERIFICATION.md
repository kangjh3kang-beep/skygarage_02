# 자체 ERP 구현 검증 기록

2026-10-19. 기준 main `14efc3b2ae7a1be7f6c1526f50968d55f4161b8d`.

원장 단계의 28개 시험을 먼저 통과한 후 원천 수신을 구현했다. 연결 단계에서 모의 수신 확인을 실제 ERP 반영으로 승격하지 않는지, 자기 승인·변조 금액·해시·시설 정보·누락 전표를 거부하는지 검증했다. 이후 100개 전표 페이지 경계, 오래된 미승인 초안의 노출, DB 지연 제약, 제공자 입력 규격을 추가했다.

## 재현 명령

```sh
npm ci
node scripts/test-erp-database.mjs --wasm --stage=1
npm run test:erp:wasm
npm run test:contracts
npm run test:erp
npm run test:database
npm run test:finance
npm run build
```

`test:erp`는 일반 OS 계정의 disposable PostgreSQL 17.10을 사용한다. 8개 병렬 재시도가 하나의 초안만 만드는지, 두 독립 승인자가 동시에 승인해도 한 번만 반영되는지 추가 검사한다. WASM은 PostgreSQL 18.6이고 운영 DB 연결 주소를 시험기에 넘기지 않는다. CLI로 생성한 마이그레이션 파일은 단계별 SQL의 정확한 결합과 비교한다.

## 검증 중 반영한 피드백

- 원천 교환에 포함된 금액뿐 아니라 거래처·실제 시설/부문도 대사한다.
- 이전 원천 마감을 ERP 마감으로 복제하지 않고, 과거 전표를 실제 수신·승인한 뒤 ERP를 마감한다. 원천의 기존 마감 이력과 잠금 날짜는 보존한다.
- 이전 모의 수신 API를 막고 실제 자체 ERP 장부 반영만 마감 근거로 인정한다.
- 업체 계획에는 지정된 네 필드만 허용하여 비밀키·활성화 플래그를 저장하지 않도록 했다.
- 큰 교환 파일을 전표별로 매번 순회하지 않도록 한 번 그룹화하고, 마감 대사도 수신 묶음당 검사한다.
- 확정 전표가 100개를 넘어도 오래된 승인 대기 초안은 화면에서 밀려나지 않도록 했다. 원장 페이지가 바뀌어도 시산표/재무상태 합계는 전체를 기준으로 유지한다.
- MUI 9의 스타일 속성 변경과 다운로드 함수의 DOM 이름 충돌을 빌드 단계에서 수정했다.
- 금융 시험기의 과거 종료 코드 문제를 반영해 정리 이후 실패 코드를 설정하며, CI는 최종 통과 건수도 확인한다.

## 범위와 한계

- 실제 기능: 자체 DB에 저장되는 ERP 전표·독립 승인·대사·역분개·보고서·마감. 입력 환경은 시험 장부이며 원천 PG 결제/현금 지급은 연결하지 않았다.
- 보안: 비공개 ERP 테이블 11개, 공개 ERP RPC 4개. DB 최고관리자 역할과 MFA를 호출마다 확인하고 직접 테이블/보조 함수 권한을 차단한다.
- 사용자 입력 증빙 참조는 파일의 진위나 세무 적격성을 자동 확인하지 않는다.
- 제공자 규격 시험의 어댑터는 테스트 파일에서만 생성한 fixture다. 실제 사업자 승인·서명 규격을 검증한 결과가 아니다.
- 현재 실행 환경에서 지원되는 브라우저 검수 도구가 없어 실제 두 관리자 로그인·MFA·화면 조작 검수는 미실시다. 정적 배포 파일 확인과 구분한다.
- 신규 예약 작업이나 외부 송금/메시지 전송을 추가하지 않는다. 처리량 SLA, 실제 은행 대사, 법정 결산/세무 신고는 별도 인수다.

최종 자동 시험 건수, 원격 PG17 결과, 마이그레이션 적용 이력, 보안 점검, 배포 SHA는 이 변경의 GitHub PR 본문에 기록한다.
