## 완료의 정의

단계의 지정 시험을 모두 통과해야 다음 단계로 진행한다. `내부 검증 통과`와 `실거래 인수`는 다른 지표다. 프로그램 시험 통과를 실제 PG·은행·ERP 승인으로 표시하지 않는다. 기존 고객 코인과 신규 시험 코인은 저장소·API·화면을 분리한다. 이 구현에는 live 모드나 실자금 송금 API가 없다.

| 단계 | 구현 | 통과 조건 | 실거래 인수 조건 |
|---|---|---|---|
| 1 | 시설·가맹점 식별, 소속 시설, 불변 요금 계약, 정수 금액 복식 원장, 요청 중복 방지 | 무권한/MFA/실거래 모드 거부, 불균형·원장 수정 거부, 동일 요청 재실행·충돌 검사 | 운영 주체·시설 계약·코인 정책 확정 |
| 2 | 서버 견적, 시험 코인 결제, 본사/시설 배분, 부분·전체 환불, 정산 배치·독립 승인·지급 결과 모형 | 잔액 부족·동시 차감·견적 만료·다른 사용자 견적·소속/타시설/무소속·반올림·이중 환불·배치 중복·실패/미확정 지급 검사 | PG 충전 승인/취소, 이용기록 신뢰성, 지급대행/은행 계약 및 현장 수취인 검증 |
| 3 | 분개·시산표·내부 원장 대사·계정 매핑·ERP JSON/CSV 교환·수신 확인 모형·기간 마감 | 차대 일치, 재전송 동일 해시, 누락/중복/다른 해시 거부, 독립 수신 확인, 마감 후 전표 차단 | 실제 ERP 제품/API/계정표/세무정책/은행 명세 대사 및 담당 회계자 승인 |
| 4 | 최고관리자 MFA 시험 워크벤치와 권한·오류 표시, 단계별 검증 결과 | 빌드·파서·CSV 안전성·API 거부·원격 PG17 동시성 통과 | 두 실제 관리자 로그인·MFA 및 사용자 조작 인수 |
| 5 | 실제 결제·지급·ERP 연결 | 1~4 통과 후 별도 커넥터와 제공자 테스트 계정 검증 | 소액 실결제→배분→환불→지급→은행대사→ERP전표의 독립 검수 |

## 조사 및 적용

- 토스페이먼츠: https://docs.tosspayments.com/reference · https://docs.tosspayments.com/guides/v2/payouts · https://docs.tosspayments.com/guides/v2/get-started/environment
  - 결제 승인과 정산/지급의 상태를 분리, 같은 요청 키로 재시도, 지급 요청 접수와 실제 성공을 구분한다. 서비스 계약과 셀러 확인은 프로그램에서 대신 승인하지 않는다.
- Stripe Connect: https://docs.stripe.com/connect/separate-charges-and-transfers
  - 결제와 수취인 배분을 분리하고 원거래·배분·환불을 연결한다. 실제 이용 시설이 수취인이며 사용자의 소속 시설은 요금/관계 판단에만 사용한다. 국내 실제 공급자 선정은 별도다.
- Odoo: https://www.odoo.com/documentation/18.0/applications/finance/accounting.html · https://www.odoo.com/documentation/19.0/applications/finance/accounting/reporting/year_end.html
  - 차변/대변 일치, 은행 대사, 마감 날짜 이후의 원장 보호를 참조한다. 내부 교환 포맷은 Odoo/더존/이카운트 실제 수입 포맷이라고 주장하지 않는다.
- Supabase: https://supabase.com/docs/guides/database/postgres/row-level-security
  - 비공개 스키마·직접 권한 회수·RLS·DB 역할/MFA 재검사·빈 search_path를 함께 적용한다.

## 반복 검증 방법

피드백 루프: 실패 재현 → 원인/영향 기록 → 수정 → 해당 회귀 시험 → 이전 단계 회귀.
성장 루프: 공식 자료의 설계 근거 → 적용 가능한 개선 후보 → 구현 → 금액 보존·권한·동시성 검증 → 다음 단계 반영.
LLM이 직접 돈을 움직이거나 원장·수수료·검증 결과를 승인하는 구조는 사용하지 않는다.

## 내부 시험 회계 가정

시험 단위 1 C = 1 모형 원. 실제 환율·환불권·선불업 정책을 확정하는 의미가 아니다. 시험 충전은 모의 현금자산 차변/이용자 예수부채 대변, 이용은 이용자 예수부채 차변/시설 미지급금 및 본사 수수료 모형계정 대변, 지급은 시설 미지급금 차변/모의 현금자산 대변으로 기록한다. 부가세·PG 비용·판매 주체에 따른 실무 분개는 회계 담당자 확정 전 적용하지 않는다. 실거래를 여는 API는 이번 릴리스에 없다.

## 외부 인수에 필요한 입력

PG와 지급대행 사업자/상점계약/비밀키(보안 입력), 시설별 수취 사업자·계좌 확인, 기본/예외 수수료·요금·환불 정책, 코인 충전/만료 정책, ERP 제품·테스트 조직·계정 매핑·수신 API, 회계 검수자. 제공 전에는 단계 5를 완료 처리하지 않는다.
