# 자체 ERP 회계와 결제사업자 확장 계획

2026-10-19. 사용자가 외부 ERP 선정 대신 자체 ERP 구축을 지정했으며 PG·지급대행사는 추후 지정한다. 이에 따라 외부 ERP 모의 수신 버튼을 자체 회계 장부의 실제 저장·독립 승인·원천 대사로 대체한다. 현재 연결 원천과 신규 장부는 시험 모드다. 현금이 이동하거나 세무 신고가 완료됐다고 표시하지 않는다.

## 범위와 단계별 통과 기준

| 단계 | 구축 내용 | 다음 단계 진입 기준 |
|---|---|---|
| 1 원장 | 장부·계정·거래처·시설/부문, 수기 초안 수정, 독립 승인, 불변 확정 전표, 역분개, 감사기록 | 무권한·자기 승인·불균형·마감 후 입력 거부, 보고서와 역분개 금액 검증 |
| 2 자체 ERP 연결 | 결제 교환 전표 자동 수신, 묶음 승인, 원천 전표/해시/금액/수취 시설 대사, 양쪽 장부 동시 마감 | 미전송·미승인·변조 전표 마감 거부, 환불/시설 지급 후 재무상태 일치, 모의 확인의 완료 승격 금지 |
| 3 사업자 확장 | 서버 공통 계약, 명시적 사업자 선택, 기능·환경 검사, 정수 금액·요청 식별자·결과 일치 검사, 웹훅 검증 경계 | 미지정/미구현 사업자 차단, 금액·거래·환경 불일치 거부, 재시도 요청 번호 보존, 미확정/최종 상태 구분 |
| 4 관리 화면 | 수신·승인, 수기 전표·역분개, 시산표·손익·재무상태·거래처 잔액·총계정원장, 기준정보·연동 계획 | 타입/빌드/응답 검증, 전체 집계와 페이지 조회 분리, 권한 실패 시 데이터 미표시 |
| 5 배포 | 원격 PG17 동시성 시험, 기존 회귀, DB 권한 점검, 사이트 배포 | 실행 로그의 최종 통과 건수, 배포 SHA와 정적 자산 일치 확인 |

각 단계의 실패를 재현하고 수정한 뒤 회귀 시험을 추가한다. 개선은 실제로 검증된 불변 조건을 기준으로 반영한다. 자동 검증 통과와 실제 관리자 로그인·MFA·화면 인수는 별도다.

## 자체 ERP의 처리 흐름

1. 사용자의 소속 여부와 관계없이 실제 이용 시설에 원천 정산금이 귀속된다.
2. 결제·정산에서 교환 파일을 만들거나 ERP에서 기간 동기화를 실행하면 원천의 미전송 전표가 자체 ERP의 승인 대기함에 저장된다. 파일 생성과 수신은 한 DB 트랜잭션이다.
3. 수신 과정은 원천 버전·시험 환경·해시·전표/행 수·계정 분류·금액·시설 귀속을 확인한다. 원천 교환 ID와 전표 ID의 중복을 DB 제약으로 막는다.
4. 작성자와 다른 최고관리자가 승인하면 ERP 전표 전체가 확정되고 원천 교환 상태가 `erp_posted`로 바뀐다. 일부만 반영되는 상태는 허용하지 않는다.
5. 원천에서 온 전표는 ERP에서 임의 수정·역분개할 수 없다. 결제 원거래의 환불·조정이 새 원천 전표로 들어온다. 수기 전표는 원본을 보존한 별도 역분개를 독립 승인한다.
6. 마감은 기간 내 미전송·미승인 전표, 진행 중인 정산, 금액·시설 불일치를 검사한 뒤 ERP와 연결 원천의 날짜를 함께 잠근다.

이전 `simulated_accepted` 교환 전표는 자체 ERP에 가져와 독립 승인해야 한다. 이전 모의 확인은 회계 반영 증거가 아니다. 신규 `simulate_erp_ack` 호출은 거부한다.

## 회계와 조회 기준

- 기본 계정: 현금/결제대기 자산, 매출채권, 코인 예수금, 시설 미지급금, 자본/기초잔액, 본사 수수료 수익, 운영 비용. 계정 분류는 불변이며 새 계정을 추가할 수 있다.
- 시설은 ERP 거래처와 시설/부문에 연결된다. 이는 본사 회계의 수취인·분석 기준이다. 시설별 별도 법인의 매출을 자동 인식한다는 의미는 아니다.
- 모든 보고서는 확정 전표를 집계한다. 시산표는 기초·기간 차변/대변·기말 잔액, 손익은 기간 수익/비용, 재무상태는 종료일 누적 자산·부채·자본·누적 손익을 계산한다.
- 계정별 차변잔액 방식이므로 부채·자본·수익의 대변잔액은 음수로 보일 수 있다. 시설/부문별 부분 필터는 부문 간 상대분개 때문에 차이가 날 수 있으며 장부 전체 차대 일치는 별도로 확인한다.
- 총계정원장은 한 페이지 최대 100개 전표다. 집계 수치는 페이지와 관계없이 전체 확정 전표를 사용한다. CSV는 해당 페이지 또는 전체 시산표임을 구분한다.
- 수신함은 승인 대기 우선 100개, 전표함은 초안 우선 100개, 화면의 감사기록은 최근 50개다. DB 감사기록은 삭제하지 않는다.
- 통화는 KRW, 금액은 정수 문자열/DB bigint다. 현재 코인 원천의 1 C = 1 모형 원 가정을 따른다. 외화·환율·VAT·PG 비용·세금계산서·법정 재무제표·회계연도 손익대체·재고·구매·급여는 이번 회계/정산 모듈의 범위에 포함하지 않는다.

## PG와 지급대행의 교체 경계

서버 계약은 `supabase/functions/_shared/payment-provider.ts`에 있다. 이번 릴리스의 등록 사업자 목록은 비어 있고 실거래 실행은 차단된다. 화면의 업체 계획은 `unassigned` 또는 `planned` 메타데이터이며 활성화 설정이 아니다.

| 구분 | 공통 계약 | 업체 지정 후 구현 |
|---|---|---|
| 결제 승인 | `confirm_payment`와 내부 거래·요청 ID, 금액, 통화 | 해당 PG 승인/조회 API, 서버 인증, 수수료·충전 분개 연결 |
| 환불 | `refund_payment`와 원래 제공자 거래 참조 | 부분/전체 취소 규격, 조회·상태 대사 |
| 지급 | `create_payout`, `lookup_payout`, 수취인 참조 | 셀러/계좌 검증, 지급 API, 결과 조회·은행 명세 대사 |
| 결과 | pending / unknown / succeeded / failed | 업체별 상태를 공통 상태로 변환; 성공 영수증과 금액 대조 |
| 웹훅 | 원본 바이트를 업체 어댑터가 검증한 뒤 표준 이벤트 반환 | 공식 서명·시간 검증, 서버 이벤트 수신함 저장, 중복/역순 처리, 재조회 |

재시도에는 같은 요청 ID를 사용한다. 사업자 선택이 없거나 미구현이면 실패로 끝나며 임의 업체로 대체하지 않는다. 공통 이벤트 키는 사업자·환경·이벤트 ID를 포함한다. 현재 규격 함수는 이벤트의 영속 중복 제거를 수행한다고 주장하지 않는다. 실제 업체를 붙일 때 서버 수신함의 유일 제약과 원장 반영을 하나의 트랜잭션으로 연결해야 한다.

비밀키·웹훅 서명 키는 서버의 보안 환경설정에만 둔다. 클라이언트의 상태값이나 `verified: true` 입력을 근거로 코인/현금을 발급하지 않는다. 실제 활성화는 업체 어댑터, 인증된 엔드포인트, 수취인 검증, 원장 연결, 계약 테스트와 소액 실거래 인수를 함께 추가하는 배포다.

## 조사한 공식 자료와 적용

- ERPNext 불변 원장: https://docs.frappe.io/erpnext/immutable-ledger-in-erpnext — 확정 원본 보존과 별도 역분개.
- ERPNext 총계정원장: https://docs.frappe.io/erpnext/general-ledger — 원천 문서 추적과 동일한 장부/기간/분석 기준의 보고서 비교.
- ERPNext 회계 차원: https://docs.frappe.io/erpnext/accounting-dimensions — 시설·부문을 계정과 분리하여 보고서 필터로 사용.
- Stripe 웹훅: https://docs.stripe.com/webhooks — 중복·역순 수신 가능성, 서명 검증과 이벤트 식별자.
- 토스페이먼츠 지급대행: https://docs.tosspayments.com/guides/v2/payouts — 지급 요청과 최종 지급 결과의 분리. 업체 선택을 의미하지 않는다.
- Supabase 함수 보안: https://supabase.com/docs/guides/database/functions — 빈 search_path, 명시적 실행 권한 회수, 호출자 권한 재검사.

## 인수와 후속 확장

현재 기능 인수는 두 최고관리자의 MFA 로그인으로 수기 전표 작성/승인과 결제 원천 동기화/승인/보고서를 확인하는 순서다. PG 지정 전에도 이 자체 ERP 흐름은 동작한다. 실제 자금과 법인 회계로 전환할 때는 회사별 기초잔액·증빙 정책·계정/세무 정책, PG·지급대행 계약과 안전한 자격증명, 실제 수취인, 은행 명세 대사, 백업 복구와 처리량 인수를 추가한다. 외부 ERP 제품 선정은 더 이상 선행 조건이 아니다.
