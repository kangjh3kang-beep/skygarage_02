## 변경한 동작

검증·개선 화면 `/admin/governance`에서 선택 현장·소스·설정 범위의 전체 과제와 증거를 조회한다. 최근 100건 밖의 과제도 25건 단위의 커서 페이지로 찾는다. 요구사항, 진행 상태, 검수 대기·만료·실패 증거, 제목·내용·절차로 필터링한다. 화면의 검색 결과 수와 현장 범위 전체 집계를 구분한다.

진행·치명·미배정·완료검수 대기·완료 과제, 증거 검수 대기, 만료 증거, 7일 내 만료되는 유효 근거를 서버 시각으로 집계한다. 미인수 요구사항마다 부족한 시험 종류·미해결 결함·선행 인수를 표시한다. 카운터는 실장비 상태나 전체 서비스의 가용성을 나타내지 않는다.

개선 시작 → 과제 등록 이후 측정·등록된 유효한 재시험 찾기 → 검수 요청 → 원자료·해시 독립 검수 → 완료로 이어진다. 실패에서 생성된 과제는 시험 종류와 환경도 일치해야 한다. 상태 변경은 UUID 영수증·revision·감사 이력을 한 트랜잭션으로 저장한다. 성공 응답을 잃어도 같은 요청으로 재시도하면 한 번만 처리한다. 오래된 입력·바뀐 내용은 거부한다. 과제의 완료는 36개 요구사항 인수와 별도다.

## 세션과 증거 유효성

기존 12개 거버넌스 공개 RPC와 새 3개 RPC는 AAL2, JWT의 session_id와 실제 Auth 세션의 소유자·만료·존재, 계정 차단·삭제 상태를 확인한다. 세션 행 공유 잠금으로 세션 삭제와 요청 순서를 맞춘다. 기존 DB 역할과 현장 배정 검사도 유지한다. 클라이언트 metadata를 권한으로 사용하지 않는다. 새 영수증 테이블은 비공개 RLS 및 직접 접근 금지다.

증거의 승인자 권한이 회수·만료되거나 계정이 차단·삭제되면 인수 근거에서 제외한다. 새 실패 이후의 과거 통과 증거, 만료·미래 측정 증거로 완료하지 않는다. 과제 종료 시에도 유효한 독립 검수자를 다시 확인한다. 검수자·종료자는 과제 작성자·담당자와 독립적이어야 하고 종료자는 해당 재시험 제출자와도 달라야 한다. 감사 쓰기 실패는 상태 변경과 영수증까지 롤백한다.

원자료 링크와 해시는 제출자의 주장이다. 시스템이 링크의 내용·실장비 시험의 진위를 자동 인증하지 않는다. 사람이 다른 계정으로 원자료와 실제 범위를 확인한다. 시뮬레이션·자동 fixture 결과를 현장 인수로 승격하지 않는다. LLM 자동 학습이나 자율 배포는 연결하지 않았다.
