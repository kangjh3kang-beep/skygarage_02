# 36개 요구사항의 단계별 업무 분장

원 계획 `2026.10-v1`의 ID·선행 관계·완료 기준을 보존한다. 코드는 `src/lib/implementation-plan.ts`, 인수는 검증 원장을 기준으로 한다. 아래는 작업 예약이며 아직 착수하지 않은 항목을 구현 완료로 표시하지 않는다. 초안 #23의 RPC 계약을 확정한 뒤 범위별 이슈를 쪼개 순차 착수한다.

Codex는 서버·권한·마이그레이션·공통 파일·CI 통합을 맡는다. Claude는 합의된 화면·이용 흐름·도움말·근거 검색과 개선 제안을 맡는다. 주 담당이 Claude인 항목에서도 DB와 공통 파일은 Codex가 변경한다. 상대 도구가 코드·시나리오를 검토하고, 운영·안전·제조사 담당자는 실제 인수를 수행한다.

| P4 | LLM 지원과 개선 순환 | 현장 격리·도구 권한·평가·승인·복귀가 모두 검증된다. |

## 반복 실행 절차

1. 최신 main과 배포·문서 버전을 기록하고 이슈 하나의 입력·출력·허용 파일·완료 조건을 고정한다.
2. 담당자가 실패 조건을 먼저 재현하고 구현한다. 공통 파일 변경은 통합 담당자에게 인계한다.
3. 계약·권한·실패·중복·지연 조건과 관련 UI를 검증한다. 실패하면 개선 이슈와 재현 근거를 만들고 같은 조건으로 재시험한다.
4. 상대 도구가 정확한 head를 검토하고 발견된 문제를 재현·수정한다. PR의 CI와 단계 완료 증거가 확인된 후 다음 구현 묶음으로 이동한다.
5. 사용자 동작의 성공률·응답시간·오류율 등 실제 수집 가능한 지표로 다음 개선 가설을 세운다. 측정 경로가 없으면 미측정으로 남긴다.
6. 모든 요구사항의 필요한 시험 종류·환경·버전·유효기간·독립 승인과 추가 범위의 인수를 충족해야 전체 완료로 판정한다. 코드·CI 점수를 운영 인수율로 환산하지 않는다.
